# ssMarket Frontend

Web app for ssMarket, an internal marketplace where company employees buy and
sell personal items: things in stock, and pre-order rounds that close at a set
time.

The API lives in a separate repository,
[ssMarket-be](https://github.com/cafefin/ssMarket-be). The two share no code;
they are connected by one environment variable (`API_URL`) and by the
backend's OpenAPI document.

## Tech stack

| Area | Choice |
|---|---|
| Runtime | Node.js 24, TypeScript 5 (strict) |
| Framework | Next.js 16 (App Router), React 19 |
| Styling | Tailwind CSS 4, shadcn/ui on Base UI, lucide-react icons |
| Server data | TanStack Query 5, openapi-fetch with types generated by openapi-typescript |
| Forms | React Hook Form 7, Zod 4 |
| Client state | Zustand 5 (one small draft store) |
| Other | qrcode.react (VietQR), sonner (toasts) |
| Tests | Vitest 5, Testing Library, Playwright; 80% coverage gate |
| Lint | ESLint 9 with eslint-config-next |
| Delivery | Docker (standalone output, non-root), GitHub Actions |

## Features

- Browse and search listings, with category and mode filters kept in the URL
  and a filter bar that stays under the header while the list scrolls.
- A "Sắp chốt đơn" row on the home page: pre-orders that close soonest.
- Listing cards that show at a glance whether an item is in stock or a
  pre-order, and when the pre-order closes.
- Post a listing in two steps: choose in-stock or pre-order, then fill in a
  form that only shows the fields for that mode. Up to five photos.
- Manage your own listings: drafts, open and closed.
- Order from a listing, pay by a per-order VietQR code, follow the order's
  payment and delivery state.
- Sellers get a summary table per listing (totals, grouping by delivery
  location, bulk actions, CSV export) and can reopen a finished pre-order.
- Seller profile with delivery location and bank details.
- Works from 360px wide: a bottom tab bar on phones, links in the header from
  768px.

## Getting started

Requirements: Node.js 24, pnpm, and the backend running on port 4000.

```bash
cp .env.example .env.local
pnpm install
pnpm dev
```

Open http://localhost:3000.

### Environment

Copy `.env.example` to `.env.local`. Never commit `.env.local`.

| Variable | Purpose |
|---|---|
| `API_URL` | Backend origin, for example `http://localhost:4000`. Read at runtime, so one build runs in every environment. |

## Scripts

```bash
pnpm dev                  # http://localhost:3000
pnpm build                # production build (standalone output)
pnpm start                # run the production build
pnpm lint && pnpm typecheck
pnpm gen:api              # regenerate src/lib/api/schema.d.ts from the backend
```

## Testing

```bash
pnpm test        # unit and component tests
pnpm test:cov    # fails under 80% coverage
pnpm e2e         # Playwright against the real frontend and backend
```

- Component tests check behaviour through roles and visible text and mock the
  API client; they never call the network.
- `pnpm e2e` needs the backend repository next to this one (`../ssMarket-be`)
  with `docker compose up -d` running. It uses its own database and ports
  (4100 and 3100), so a running `pnpm dev` and its data are not touched.

## Architecture

The browser only talks to this app. `src/proxy.ts` forwards `/api/*` to the
backend at `API_URL`, which is read at runtime, so session cookies stay on one
origin and the same Docker image runs in every environment.

API types in `src/lib/api/schema.d.ts` are generated from the backend's OpenAPI
document with `pnpm gen:api`. An API change is two commits: the backend first,
then the regenerated types and the matching change here.

```
src/
├── proxy.ts              forwards /api/* to the backend; redirects signed-out visitors
├── app/
│   ├── globals.css       design tokens
│   ├── login/            public
│   └── (app)/            everything that requires a session
├── components/
│   ├── ui/               shadcn/ui primitives
│   ├── brand/            logo mark, wordmark
│   ├── layout/           header, search, user menu, navigation, phone tab bar
│   ├── listings/         card, filters, closing-soon carousel, detail view
│   ├── sell/             listing form, my listings
│   ├── orders/           order panel, order page, lists, seller summary
│   └── profile/
└── lib/
    ├── api/              typed client, session refresh, query hooks
    ├── listings/         URL filters, form schema, draft store
    ├── orders/           order arithmetic shared with the backend's rules
    ├── theme/            contrast helpers and the palette contrast gate
    └── format/           money, dates, closing times, initials
e2e/                      Playwright scenarios
```

Pages under `app/` stay thin: each renders one component from `components/`,
which holds the behaviour and has the tests.

## Design system

[DESIGN.md](./DESIGN.md) is the source of truth; its tokens are declared in
`src/app/globals.css` and exposed as Tailwind classes.

- Three colours carry meaning. Blue is something you can press. Green is
  available or done. Orange is a pre-order and its closing time.
- Bricolage Grotesque for headings, prices and the wordmark; Inter for other
  text; Geist Mono for codes people copy.
- Every text and background pair is checked for WCAG AA contrast by a test
  (`src/lib/theme/contrast.test.ts`), so a palette change that hurts
  readability fails the build.

## Docker

```bash
docker build -t ssmarket-fe .
docker run -e API_URL=http://host.docker.internal:4000 -p 3000:3000 ssmarket-fe
```

The image is a multi-stage build on `node:24-alpine`, uses Next.js standalone
output and runs as the `node` user.

## Continuous integration

GitHub Actions runs on every pull request and on pushes to `production`:
install, lint, typecheck, tests with the coverage gate, build, and a Docker
image build.

## Branches

- `production` is the default branch.
- Work happens on `feat/...`, `fix/...` or `chore/...` branches and reaches
  `production` through a pull request. Commits follow Conventional Commits.

## Notes

- This project uses Next.js 16, which differs from earlier versions; see
  [AGENTS.md](./AGENTS.md) before changing framework-level code.
- Listing images come from `/api/media/...` behind the session cookie, so the
  app uses a plain `<img>`; the Next.js image optimizer cannot fetch them.
- Sign-in links are plain `<a href="/api/auth/google">`, not `next/link`,
  because they must be full navigations that reach the backend.
- The interface is Vietnamese only for now. Code, comments and commits are
  English.
- See [CLAUDE.md](./CLAUDE.md) for the full conventions.
